# 每日签到脚本

`E:\router-checkin` 是独立的 AnyRouter/AgentRouter 每日签到项目，不依赖
`E:\wxbot-ipad`，也不与 `E:\newcheckin` 合并。

`anyrouter.top`（2 个账号）和 `agentrouter.org`（4 个账号）每天自动签到。

- 脚本：`tools/daily_checkin.py`
- 包装：`tools/daily_checkin.cmd`（给任务计划用）
- 配置：`tools/checkin_sites.json`（gitignore，示例见 `checkin_sites.example.json`）
- 日志：`logs/daily_checkin.log`
- AnyRouter 登录态：配置里每个账号的 `cookies.session`
- AgentRouter 登录态：配置里每个账号的 `username` / `password`
- 浏览器 profile：`data/checkin_profiles/<profile>/`（只有 AgentRouter 用）

开发过程和各种踩坑的完整记录见 `docs/开发过程记录.md`。

## 运行时机（重要）

**两个站的「每日」口径不一样：**

| 站点 | 重置时刻 | 含义 |
|---|---|---|
| AnyRouter | UTC 0 点 = **本地 08:00** | 08:00 之前跑会白跑：接口返回成功但不发放 |
| AgentRouter | 本地 0 点 | 随时可跑 |

所以统一排在**本地 08:00 之后**跑一次，两个站都覆盖。

## AnyRouter 配置

只需要浏览器登录后的 `session` Cookie：

```json
{
  "name": "anyrouter-1",
  "base_url": "https://anyrouter.top",
  "cookies": { "session": "这里填 session 的值" },
  "session_cookie": "session",
  "api_user": "12345",
  "proxy": "http://127.0.0.1:7890",
  "enabled": true
}
```

Cookie 位置：已登录 AnyRouter 的浏览器 → F12 → `Application` → `Cookies` →
`https://anyrouter.top` → `session`。

⚠️ **`session_cookie` 存的是 Cookie 的名字（`"session"`），不是它的值。**
值放 `cookies` 里。这两个字段被填反过一次，脚本会按长度认出来并自动纠正
（Cookie 名字不会有几十个字符），但那是兜底，看到提醒应该回头改对配置。

`cookies` 也支持完整 Cookie 字符串：`"cookies": "session=SESSION_VALUE"`。

`api_user` **推荐填写**（站点用户 ID，登录后在浏览器控制台 `localStorage.user.id`
可以看到）。第一次查 `/api/user/self` 时要带 `New-Api-User` 头，不填的话站点可能
直接回 401「未提供 New-Api-User」，脚本会报「api_user 缺失或与登录用户不匹配」。

启用的账号里如果还留着示例的占位内容（含「这里填」、`AgentRouter 用户 ID` 等），
脚本启动时直接报错退出，不会拿占位串去请求。

## AgentRouter 配置

用**邮箱/用户名 + 密码**登录，不走 OAuth：

```json
{
  "name": "agentrouter-1",
  "base_url": "https://agentrouter.org",
  "kind": "relogin",
  "checkin_path": "",
  "api_user": "AgentRouter 用户 ID",
  "username": "邮箱或用户名",
  "password": "密码",
  "proxy": "http://127.0.0.1:7890",
  "enabled": true
}
```

OAuth（LinuxDO / GitHub）注册的账号可以在站点的**个人设置**里绑定一个密码。
没填 `username` / `password` 的账号直接报「需要人工重新登录」，不会打开浏览器，
也不会动 profile 里的 Cookie；暂时不用的账号请设 `"enabled": false`。

`api_user` 是站点用户 ID，用于在退出重登前读取 `/api/log/self` 判断当天是否已经
签到，**预检必须用到它**。四个账号都应填写；它不是密码，也不是 Cookie。登录后可以
在浏览器控制台的 `localStorage.user.id` 看到。缺少该字段、或填错（站点回 401
「New-Api-User 与登录用户不匹配」）时，脚本会为了保护现有登录态而不执行退出重登，
并报告“签到状态未知”。

⚠️ **凭据不要填进 `oauth_path`**（那个字段是历史遗留的 OAuth 路径，现在不再使用）。
这个也被填反过一次，脚本同样会自动纠正并提醒。

### 为什么不走 OAuth

实测 LinuxDO OAuth 走不通：直接访问 `/oauth/linuxdo` 会落到 `/login?expired=true`；
走登录页点按钮会开弹窗到 `connect.linux.do/oauth2/authorize`，但该页在 headless
下 body 全空、不回跳。profile 里 linux.do 的登录态是有效的（`_t` 和
`cf_clearance` 都在），卡的是授权页渲染。

### 为什么必须用持久化 profile

`/api/user/self` 被阿里云 WAF 的**人工滑块**挡着——但只在**临时浏览器**里会触发。
用持久化 profile（真实 Edge channel）启动就正常。这一点做过对照：临时浏览器下
有头/无头、走代理/直连、页内合成 fetch / 站点前端自己发的 XHR，全部命中滑块。

profile 里保存两样东西：

- **WAF 放行 Cookie**（`acw_*`）：不触发滑块全靠它，退出时也保留。
- **上一次运行留下的 `session`**：预检用它查今天的系统日志，确认已签到就不再
  退出重登（重跑保护）。每天真正的签到仍然是清掉它后用密码重新登录完成的。

profile 里没有 `session`（首次运行、profile 被清过）时没有可保护的登录态，脚本
跳过预检直接用密码登录。

## 日常使用

```powershell
python tools\daily_checkin.py --verbose             # 全部账号（本地 08:00 之后）
python tools\daily_checkin.py --only anyrouter-1    # 单个账号
python tools\daily_checkin.py --notify-url https://example.invalid/webhook
```

不给 `--notify-url` 时读环境变量 `CHECKIN_NOTIFY_URL`；都没有就不推送。webhook
只接受 `http://` / `https://`，返回 3xx 当推送失败（不跟随重定向）。请求体格式见
README 的「通知」一节。

退出码：

| 退出码 | 含义 |
|---|---|
| `0` | 所有启用账号都是「签到成功」「今天已签过」或「签到已提交（未能核对）」；或没有启用的账号 |
| `1` | 至少一个账号「需要人工重新登录」「签到状态未知」或「失败」；整轮运行中断也算 |
| `2` | 配置无法加载（找不到、JSON 语法错误、字段错误、占位内容未改），或使用了已废弃的 `--notify` 参数 |

配置错误和整轮中断也会写进日志（名字记为 `daily_checkin`），并尽量推送通知。

六个账号串行跑完约三分钟（账号之间有 5 秒延迟）。

**失败了不要连着重试。** 每次运行包含一整套 WAF 预热导航加多次 API 调用，
403 期间的重试会给阿里云的限流计数器续命。实测限流窗口超过 37 分钟、
不到 2.5 小时，遇到 403 隔两小时以上再试一次即可。预热每次最多导航 3 次，
看到限流页立即停止。

## 挂到任务计划

```powershell
schtasks /create /tn "router-checkin-daily" /tr "E:\router-checkin\tools\daily_checkin.cmd" /sc daily /st 08:10
```

时间必须在本地 08:00 之后（见上面的「运行时机」）。

## 两个站的流程

| `kind` | 站点 | 流程 |
|---|---|---|
| `refresh` | AnyRouter | 临时浏览器过 ESA 挑战 → 注入 `cookies.session` → 页内 fetch `/api/user/self` → POST `/api/user/sign_in` → 再查一次取余额 |
| `relogin` | AgentRouter | 持久化 profile → **预检**（profile 有 `session` 时过 WAF 并查今天的系统日志；已签到就结束）→ 只清 `session` Cookie（= 退出）→ 过 WAF → 密码登录 → 页内 fetch `/api/user/self`（这一步即完成签到） |

两个关键点：

1. **API 请求必须走浏览器页内 `fetch`，不能用 HTTPX/requests/curl。**
   实测同一上下文、同一组 Cookie、同一代理出口下，页内 fetch 拿到 401（正常的
   未登录），HTTPX 拿到 403——阿里云 ESA 认的是 Chrome 的 TLS/HTTP2 指纹，
   改请求头没用。只有页面跳转导致执行上下文被销毁时才退回 `page.request`。
2. **AgentRouter 的「退出」是精确清掉 `session` 这一个 Cookie**，不是丢掉整个
   profile，也不是清整个域。退出后 WAF 预热失败、登录失败或中途出错，都会把原来的
   `session` 放回去。

## 「今日已签到」怎么判

两个站的判据不一样，都是被迫的：

| 站点 | 判据 | 为什么 |
|---|---|---|
| AnyRouter | 签到前后的额度是否相等 | 站点不记签到日志，且重复签到也返回 `success: true` |
| AgentRouter | 系统日志 `/api/log/self?type=4` 里今天的签到记录早于本次运行 | 查 `/api/user/self` 就等于签到，拿不到「签到前」的额度 |

AnyRouter 的 `sign_in` 响应还有个辅助信号：首次签到 `message` 是
「签到成功，获得 $25 额度」，重复签到是空串。脚本拿它做否决——`message` 非空即
确定本次签到成功，不再看额度。「已签过」的特征词只在 JSON 的 `message` 里找，
响应不是 JSON 时才看原文；只读的 `/api/user/self` 那一步永远不会判成「已签过」。

## 结果分类

| 状态 | 含义 | 算失败吗 |
|---|---|---|
| 签到成功 | `success: true` 且确认是本次签上的 | 否 |
| 今天已签过 | 见上一节的判据 | **否**（每天第二次跑的正常结果） |
| 签到已提交（未能核对） | AgentRouter 密码登录已成功、签到已触发，但核对用的 `/api/user/self` 被滑块挡了，读不到余额 | **否**（余额长期不涨再人工滑一次） |
| 签到状态未知（未执行重登） | WAF、`api_user` 或系统日志无法读取 / `api_user` 与登录用户不匹配；为保护现有登录态，未执行退出重登 | 是 |
| 需要人工重新登录 | HTTP 401 会话失效 / 缺凭据 / 登录页明确提示凭据错误 | 是 |
| 失败 | 403（WAF、限流）、429、5xx、登录页打不开或找不到表单、明确的业务失败、整轮中断 | 是 |

区分「已签过」和「真失败」很重要：混在一起会让任务计划每天报红，红久了就没人看了。

**重跑保护**：AgentRouter 每次执行前先用当前 profile 查询今天的系统签到记录。
已经签到就直接结束，不清 `session`、不退出、不重新登录；只有明确读到今天尚未签到，
或服务端明确回答会话已失效（401「未登录」「access token 无效」），才执行退出重登。
预检遇到 WAF、网络或用户标识问题时会报告「签到状态未知（未执行重登）」，
保留原登录态，确认原因后再单独重试。

**403 不会提示重新登录**——那是 WAF 或限流，不是账号问题。

## 排错

**启动就报「xxx 还是示例占位内容」**
配置是照模板抄的、还没改。填入真实值，或把该账号设为 `"enabled": false`。

**AnyRouter 报「配置中未发现 session Cookie」**
在配置里填 `"cookies": {"session": "..."}`。这个站不用 `--login`。

**报「WAF/限流未通过」（403）或「ESA 自动限流」**
阿里云限流。等两小时以上再试一次，不要连着重试；也可以换代理出口。

**AnyRouter 报「WAF 挑战未通过」**
ESA 的 JS 挑战没跑完（Cookie 已下发但页面仍是验证页，或 API 返回的是验证页）。
稍后单独重试一次；持续出现就换代理出口。这个站不用 `--login`。

**AgentRouter 报「签到已提交（未能核对）」或「预检无法通过 WAF」**
持久化 profile 开始触发滑块了。偶发不用管；连续多天出现时人工滑一次：

```powershell
python tools\daily_checkin.py --login agentrouter-1
```

**报「登录页找不到邮箱/用户名表单」「登录页打不开」**
通常是网络抖动，脚本已经内部重试 3 次，记为「失败」，原登录态已恢复。
持续出现说明站点登录页改版了。

**AgentRouter 报「登录未完成（仍停在登录页）」**
页面上出现了凭据错误提示（如「用户名或密码错误」）时记为「需要人工重新登录」，
核对配置里的 `username` / `password`；没有凭据错误提示时记为「失败」，多半是
网络或页面问题，稍后重试。两种情况都会恢复原登录态。

**报「会话已失效」（401）**
AnyRouter 是 `session` 过期了，重新从浏览器取一份填进配置。详情里带着服务端原话。

**报「api_user 缺失或与登录用户不匹配」/ 预检报「api_user 配置有误」**
`api_user` 没填或填成了别的账号的 ID。按上面的方法从 `localStorage.user.id` 取。

**日志里中文乱码 / `.cmd` 报「'X' 不是内部或外部命令」**
`.cmd` 必须是 **CRLF** 换行。实测纯 ASCII 的批处理用 LF 没事，
但**一旦文件里有中文，LF 就会让 cmd.exe 把行拆错**，而且退出码会变成 0
（任务计划看不出失败）。已有测试钉住这条：
`tests/test_daily_checkin.py::BatchFileLineEndingTests`。

## 为什么用浏览器，而不是纯 HTTP 方案

历史上试过直接用 requests 发 HTTP 请求，实测：

| 站点 | 实测结果 |
|---|---|
| `anyrouter.top` | 挂在阿里云 ESA 后面，**任意路径**都返回 JS 挑战页，requests 根本到不了 API |
| `agentrouter.org` | API 可达，但 `/api/user/self` 对没有放行记录的浏览器上下文要人工滑块 |
| 两站 | **都必须走代理**（直连分别 SSLError / ConnectTimeout） |

即便拿到了 WAF Cookie，HTTPX 仍然过不去（TLS 指纹），所以最终 API 请求也留在
浏览器里。刻意不点页面按钮、不抓 DOM——登录后的 UI 会变，写死选择器等于赌；
唯一必须操作 DOM 的地方是 AgentRouter 的登录表单。

## 与其他项目的关系

本项目按账号配置中的 `proxy` 字段独立访问两个站点，不读取 wxbot 的代理策略、
配置、登录态或通知模块，也不读取 `E:\newcheckin` 的任何文件。

以后排查代理问题时只检查 `tools\checkin_sites.json`、当前代理出口和本项目日志。
